# CORELINE iOS Companion App

## Status

**Concept / planned development.**

The iOS application described in this directory is a proposed
companion application for the future CORELINE sensor module.

No production iOS application is currently implemented in this
repository.

The mechanical CORELINE prototype is designed to function independently
of a smartphone application or electronic sensor system.

---

## Purpose

The proposed iOS application may provide an interface for viewing
and managing data generated by the optional CORELINE sensor module.

Potential functions include:

- connecting to the sensor module using Bluetooth Low Energy (BLE);
- displaying sensor connection status;
- displaying battery status;
- receiving IMU and pressure-sensor data;
- visualizing pressure distribution;
- recording test sessions;
- reviewing recorded measurements;
- exporting user-controlled sensor data.

These functions remain subject to prototype testing and development.

---

## Proposed Architecture

A future iOS implementation may include the following components:

### BLE Communication

Responsible for:

- discovering compatible CORELINE sensor modules;
- establishing and maintaining a BLE connection;
- receiving sensor packets;
- monitoring connection state;
- handling reconnection and communication errors.

The implementation is expected to use Apple's CoreBluetooth framework.

The BLE service and characteristic structure has not yet been finalized.

### Data Layer

Responsible for decoding sensor information into the provisional
CORELINE data model.

The proposed data structure is documented in:

`software/api/data-format.md`

The schema may change as the electronics and sensor architecture are
developed.

### Visualization

Potential visualizations include:

- pressure-channel values;
- relative pressure distribution;
- device orientation;
- movement-related IMU measurements;
- battery and connection status.

Visualizations are intended primarily for prototype evaluation and
user feedback.

They should not be interpreted as medical diagnostic information.

### Session Recording

A future application may allow sensor measurements to be recorded as
sessions for later analysis.

Possible session information includes:

- start and end timestamps;
- sensor samples;
- device status;
- calibration state;
- optional user notes.

The final storage format has not yet been selected.

---

## Privacy Principles

The companion application should follow a privacy-first architecture.

Design goals include:

- local data storage by default;
- minimal collection of personally identifiable information;
- explicit user control over data export or sharing;
- no mandatory cloud account for basic sensor operation;
- encrypted communication where technically supported;
- clear deletion and data-retention controls.

The application should not transmit sensor data to external services
without explicit user action or consent.

---

## Platform Direction

The initial iOS prototype is expected to use standard Apple development
tools and frameworks.

Possible implementation technologies include:

- Swift;
- SwiftUI;
- CoreBluetooth;
- local application storage for recorded sessions.

Specific frameworks and minimum iOS versions will be selected when
application development begins.

---

## Development Stages

A possible development sequence is:

1. BLE discovery and connection prototype.
2. Reception of simulated sensor packets.
3. Integration with physical prototype electronics.
4. Basic real-time sensor visualization.
5. Calibration workflow.
6. Local session recording.
7. Data export and testing tools.
8. User-interface refinement and reliability testing.

---

## Relationship to Android Application

The Android and iOS companion applications are intended to use the same
CORELINE sensor data model and BLE communication protocol.

Platform-specific implementations may differ, but sensor packet
definitions and exported data structures should remain compatible
between platforms.

Shared data definitions are documented in:

`software/api/data-format.md`

---

## Current Repository State

This directory currently documents the planned iOS software
architecture.

Application source code will be added when development of the sensor
module and communication protocol reaches the appropriate stage.

Until then, the specifications in this repository should be considered
provisional and subject to change.
